# 执行版本的评估准备批次

本目录绑定已提交的应用代码与已安装运行依赖，冻结清单是准备快照。原始 PDF 校验通过；全部 120 条输入仍是待人工复核的 AI 草稿，全部系统预测为 null。两份独立人工表各 140 项为空，120 次流程运行表为空，应用章节/运行夹具 ID 未观察。

原先注入正确数的二十个控制器场景保存在 controller-regression-cases.json，仅供确定性控制测试。真实流程改用 actual_grade_v1：提前固定阈值、目标分支及作答策略，根据观察到的实际整数成绩检查状态转换，不能要求模型返回指定分数。目标分支未出现应记录不匹配，不能反复重跑直到通过。reference/wrong_reference 是编写的测试输入，不能作为独立质量标签或真实学生表现。

正式采集前需要真实服务和模型配置、完整讲义页覆盖、独立课程/章节夹具，以及两位真实成员对协议、映射和作答策略的复核。evaluation_protocol 故意保持未复核；采集器会阻止把该准备快照当作已完成的正式评估。模型配置或代码改变后应创建新的命名正式批次，再重新生成运行绑定。

此处人工表绑定的是尚无输出的输入快照，只能用于准备和检查输入。实际输出合并后，必须针对新的 observed-dataset.json 重新生成独立盲标表，再由两人分别填写及裁决分歧。

完整操作见 docs/FORMAL-COLLECTION.md、docs/EVALUATION.md 和 docs/LIVE-INTEGRATION.md。所有 pdf_path 从仓库根目录解析。开发仅用第 2、3 讲；最终保留第 4、6、8 讲。题目、候选答案、评分点与人工判断不得进入讲义检索库。

后续 Windows 自建 API 进程重启修复使用新的准备快照 `../execution-20261112-r2`。本快照保留原配置和空白观察，不能冒用为修复后代码的正式运行。
