# CitePath 功能核对与本次续开发记录

核对日期：2026-11-11。代码基线：默认分支 `develop` 的 `c93fb9c`。

本报告把用户提供的 18 步流程表和评分规则草案作为需求参考；以下区分已有代码、本次修改和仍需真实环境验收的部分。代码存在、自动化测试通过、真实服务联调和正式评估是不同的完成层级。

## 原仓库已经具备的功能

基线已经实现用户注册和 Cookie 登录、课程管理、PDF 上传与内容去重、Docling 按页解析、保留原始页码、结构分块和跨页衔接、Milvus 向量与 BM25 混合检索及重排。React 前端已有真实课程、学习计划、日历、逐题练习、考试、历史报告和独立问答的接口调用。

学习计划能从资料生成章节、概念、引用页和按日期安排的任务。练习原来采用按概念反复学习与复习的模式；它不是评分草案要求的“最多两轮、每轮独立判分”流程。考试已有选择题和简答题、草稿保存、得分及错题报告。独立问答已有讲义检索、历史对话、学习记录查询和有标识的网页补充来源。

基线存在几项关键缺口：模型批改缺失可能被当成零命中；练习可能无限补练；通过线不可按会话配置；先标记入库完成再写向量；重新生成计划会删除章节、练习记录和掌握进度。前端对接文档仍停留在早期“规划和练习未接入”的描述。

## 对照 18 步的状态

| 步骤 | 基线已有 | 本次续开发后的状态与边界 |
| --- | --- | --- |
| 1. 统一规则与接口 | 有判分函数、数据表和前后端 API，但未完全符合草案 | 增加严格判分、会话固定通过线、最多两轮、失败不出正式分数等规则；补充接口文档和回归测试。 |
| 2. 启动基础服务 | Docker Compose 配置了 MySQL、Milvus、etcd、MinIO 和 Attu，并配置持久化 | 配置保留；本次环境的 Docker daemon 不可用，未完成真实数据库和向量库联调。 |
| 3. 封装部署 Agent API | FastAPI、统一模型入口、60 秒超时、有限重试 | 补充模型用量日志、批改失败保护与新增接口；示例配置中的密钥替换为占位符。是否可实际调用模型仍需有效配置验证。 |
| 4. 上传课程资料 | 上传、学生说明、内容哈希去重、资料列表，但只存解析页 | 原始 PDF 在向量索引前原子保存到本地存储；新增有登录和所有权检查的原文件查看接口，引用可打开对应 PDF 页。向量失败仍保留原文件及可重试错误状态；重传同一文件复用文档编号，并可补回旧资料缺失的原 PDF。 |
| 5. 解析并入库 | Docling 页面解析、原始 PDF 页码、清理页眉页脚、分块与混合检索 | 既有能力保留；真实讲义解析、模型下载和检索质量仍需端到端验收。 |
| 6. 检查入库状态 | 有 `pending/complete` 字段，但过早置为完成 | 只有关系数据提交且向量写入成功后才置为 `complete`；失败保存 `ingest_error`，禁止基于未完成资料生成新题；已有题目和报告可恢复。 |
| 7. 生成学习计划 | 按资料和目标生成章节、概念、引用页、日期和练习入口 | 首次生成维持模型规划；预计学习时长和主动追问补充信息尚未实现。 |
| 8. 第一轮练习 | 有真实出题、题型检查、引用范围校验和持久化 | 改为先生成并原子保存整轮题组；每个章节概念生成选择题和简答题，恢复时复用原题。 |
| 9. 提交与批改 | 有选项匹配和简答得分点判定 | 选项严格匹配；简答固定按命中比例至少 80% 判断；模型超时、缺失、重复或非法命中结果报错，不自动判错、不形成无效正式成绩；草稿可保存。 |
| 10. 错题反馈与复习 | 有错题解释、概念统计和引用 | 只为错题请求补救解释；报告保存文档 ID 和原始 PDF 页码。解释是否真正受到引用页支持仍需人工标注评估。 |
| 11. 通过或补练 | 原练习按掌握状态循环，考试通过线固定 80% | 新练习默认通过线 80%，建会话时可配置且会话内固定；第一轮通过结束，失败只针对薄弱概念生成第二轮；判断使用未四舍五入的数值。 |
| 12. 第二轮结束与报告 | 有报告，但没有正式两轮终止结果 | 第二轮无论是否通过都结束，区分第一轮通过、第二轮通过、两轮后仍未通过；逐轮报告成绩、剩余薄弱概念和来源，不平均两轮分数。旧记录明确标识为历史规则记录。 |
| 13. 动态调整计划 | 重新生成会删除旧章节及其练习进度 | 现有计划改为重新排期：保留章节 ID、已完成任务、原题与报告，只移动未完成任务；根据最新报告的薄弱概念和备注关键词排序。章节边界固定，后续上传的新资料不会自动加入既有计划，完整重新分析/计划版本管理仍待开发。 |
| 14. 中途保存与恢复 | 有题目、作答和考试草稿存储 | 补充练习草稿、整轮题组持久化、重复请求返回已保存状态、MySQL 锁与事务保护；模型失败后保留当前题及草稿供重试。跨进程锁和实际网络中断仍需真实 MySQL 场景验证。 |
| 15. 独立问答 | 有讲义引用、历史记录、学习状态工具及网页回退 | 保持问答对练习分数和轮次的只读边界；讲义来源与外部网页来源分开展示，证据不足时说明。新增隔离回归检查。 |
| 16. 异常与执行记录 | 有有限模型重试和若干接口异常处理 | 补充严格批改异常、可重试入库失败、模型调用状态/耗时/token/可配置估算成本日志；不把未知用量或未知价格当作零成本。 |
| 17. 持续测试 | 有解析、分块、题目格式、计划和判分的单元测试 | 扩充判分边界、模型失败、两轮流转、重复提交、恢复、草稿 API、入库和重新排期测试；测试使用模拟依赖，不等于真实端到端或真实模型质量验收。 |
| 18. 正式评估与复现 | 未发现正式评估结果或人工标签 | 增加评估与冻结配置的准备工具/说明。Lectures 2、3 用于开发；4、6、8 用于最终评估，最终标签不得用于调试。尚未执行人工对照及正式验收。 |

## 验证范围

本次实际运行结果：后端 `unittest` 的 152 项测试全部通过（其中包含 20 个固定流程子场景）；浏览器模拟 API 的 18 项检查全部通过；前端生产构建通过；lint 退出码为 0，仍有原有警告。配置冻结脚本已成功运行。这里的结果仅代表下述测试范围。

本次增加的测试通过 mock 隔离 MySQL、Milvus 和模型调用，用于检查程序规则与状态转换；前端构建和 lint 用于检查类型、产物及静态问题。具体执行结果以本次交付的测试日志为准，不把测试数量写成真实教学效果指标。

没有在本环境证明以下结果：真实 PDF 上传到数据库和向量库后的完整链路、真实模型简答判断准确率、引用的语义支持率、20 个真实服务会话的成功率、真实 token 成本或延迟。Docker daemon 不可用；没有使用 Lectures 4、6、8 的最终人工标签进行开发或声称达到评估目标。
